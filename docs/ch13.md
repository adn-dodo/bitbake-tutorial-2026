patch using the [tutorial-patch class](../ch13/meta-tutorial/classes/tutorial-patch.bbclass).

```text
do_fetch -> do_unpack -> do_patch -> do_build
```

The recipe selects the patching class instead of the fetch-only class:

```bitbake
SUMMARY = "A tiny source tree patched by our own task"
SRC_URI = "file://hello.c"
S = "${UNPACKDIR}"

inherit tutorial-patch

do_build () {
    cat "${S}/hello.c"
}
```

```bash
bitbake hello-host
cat tmp/work/hello-host-1.0-r0/sources/hello.c
cat tmp/work/hello-host-1.0-r0/temp/log.do_patch
bitbake -g hello-host
```

The unpacked source now calls `puts("Hello from standalone BitBake.");`.
The log says `patching file hello.c`. The checked-in source still says
`Hello before patch.`: never patch the layer's original files in place.

## File search is a separate concern

The C source lives in the recipe's `files/` directory, already in `FILESPATH`.
The patch lives in **meta-two**, supplied by an
[append file](../ch13/meta-two/recipes-advanced/hello-host/hello-host_1.0.bbappend):

```bitbake
FILESPATH:prepend := "${THISDIR}/files:"
SRC_URI += "file://greeting.patch"
```

Our configuration now defines `THISDIR` as
`${@os.path.dirname(d.getVar('FILE'))}`; the minimal copied configuration did
not supply it. `THISDIR` must be captured immediately with `:=` while parsing this append.
The trailing colon separates the added directory from the existing search
path. Prepending means this directory is searched first.

```bash
bitbake-layers show-appends
bitbake -e hello-host | grep '^FILESPATH='
```

This project edits `FILESPATH` directly. `FILESEXTRAPATHS` is a familiar
OE-Core convention, but merely setting it in bare BitBake would do nothing
without code to turn it into `FILESPATH`.

## We, not the fetcher, define patch policy

The fetcher copies both `hello.c` and `greeting.patch` into `UNPACKDIR`.
It does not automatically apply a file because its suffix is `.patch`.
Our class explicitly runs:

```sh
patch --batch --forward -p1 < "${PATCH_FILE}"
```

`[dirs] = "${S}"` sets the working directory. `-p1` strips the leading `a/`
and `b/` path component in the unified diff. `--batch` prevents interactive
prompts and `--forward` rejects a repeated/reversed patch. Shell task failures
propagate; BitBake prints the failing log location.

This intentionally small class supports **one explicitly selected patch**.
It does not implement OE-Core's patch series, `apply=`, quilt integration,
or patch-status policy. Adding more URLs alone does not apply more patches.

## Rebuild from a known source tree

```bash
bitbake -C unpack hello-host
```

This invalidates unpack, recreates its directory, and requests the default
build graph. Patch and build then run against fresh sources. In contrast,
`bitbake -f -c patch hello-host` tries to apply the patch to the existing tree
and should fail if it is already patched. Recover with `-C unpack`.
Do not suppress a patch error to make a build appear successful.

Changing the local patch content changes the fetch task's file checksum,
which propagates through unpack to patch. Chapter 16 measures this mechanism.

From the repository root, `bash tests/check-ch13.sh` verifies the patched
copy, unchanged original, graph edge, and successful fresh-tree rebuild.
