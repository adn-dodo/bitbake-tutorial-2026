```bitbake
SUMMARY = "Configure, compile and install a small host program"
SRC_URI = "file://hello.c file://Makefile"
S = "${UNPACKDIR}"

inherit tutorial-build

do_build () {
```

The `hello-host` recipe now builds the Chapter 13 source with the host C
compiler. Install `cc`, `make`, libc development headers, `patch`, and the
usual core utilities (on Ubuntu: `build-essential patch`). No cross compiler,
target sysroot, root privileges, or Yocto checkout is required.

From `ch14/build`:

```bash
bitbake hello-host
tmp/work/hello-host-1.0-r0/dest/usr/bin/hello-host
```


## Supply the build lifecycle yourself

[tutorial-build.bbclass](../ch14/meta-tutorial/classes/tutorial-build.bbclass)
inherits the fetch/patch classes and adds:

```text
fetch -> unpack -> patch -> configure -> compile -> install -> build
```

The actual task names have the `do_` prefix. Some earlier `before do_build`
edges remain; redundant prerequisites do not run a task twice.

1. **Configure** checks that `TUTORIAL_CC` exists and writes `config.mk` with
   the selected compiler and flags. It cleans only `B`.
2. **Compile** invokes the fetched
   [Makefile](../ch14/meta-tutorial/recipes-advanced/hello-host/files/Makefile)
   from `B`. Make reads `config.mk` and compiles the source from `S`.
3. **Install** recreates `D` and installs the executable at mode `0755` under
   `D/usr/bin`.
4. **Build** runs the installed host program, demonstrating the output.

These are our class's tasks, not magic names that BitBake auto-implements.
We deliberately do not inherit OE-Core's `autotools`, `cmake`, or `meson`.

## Keep directories distinct

| Variable | Path below `tmp/work/hello-host-1.0-r0` | Contents |
|---|---|---|
| `WORKDIR` | `.` | The whole recipe workspace |
| `S` | `sources` | Unpacked/patched C source, Makefile and patch |
| `B` | `build` | `config.mk` and compiled executable |
| `D` | `dest` | Staged `usr/bin/hello-host` |
| `T` | `temp` | Logs and generated task scripts |

`D` is a destination tree, **not your host's `/`**. Install never writes to
`/usr/bin`. There is no package, root filesystem or bootable image.

```bash
cat tmp/work/hello-host-1.0-r0/build/config.mk
cat tmp/work/hello-host-1.0-r0/temp/log.do_compile
find tmp/work/hello-host-1.0-r0/dest -type f
bitbake -g hello-host
```

The compile log shows the host compiler invocation. A missing compiler or a
compile error fails the task and prevents install from running.

## Configuration changes and rebuilding

In this chapter's `build/local.conf`, try:

```bitbake
TUTORIAL_CFLAGS = "-O0 -g -Wall -Wextra"
```

Then run `bitbake hello-host` and inspect `config.mk` again. This metadata
change invalidates configure and its successors through their signatures.
Remove the assignment to return to the default `-O2` build.

`bitbake -c compile hello-host` stops at compilation, whereas
`bitbake -C compile hello-host` invalidates compile and requests the default
graph including install/build. To reapply patches, start at unpack instead.

Our host tools are external prerequisites; their binary contents are not
automatically hashed or staged. This is **not** a hermetic/reproducible
cross-toolchain environment. OE-Core adds substantial toolchain and sysroot
policy beyond the task engine shown here.

Run `bash tests/check-ch14.sh` from the repository root to check the exact
program output, installation mode, separated build tree, and graph edges.
